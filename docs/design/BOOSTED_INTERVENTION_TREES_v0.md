# Boosted Intervention Trees over a Replay Tree（v0，2026-10-04）

这份文档把两个想法合在一起：
- Dream-RSI 把历史轨迹存成一棵发现树，再拿它当回放模拟器；
- XGBoost 的做法是每一轮新学一棵树，去拟合当前的残差。

二者合起来，就是我们"诊断 → rubric → 干预"闭环的下一版。它接着 MATH_FORMALIZATION_v1 的 §2–§6 和 §10 往下写。

## 0. 动机（实验事实）
- H2 + D10 已经到 0.85（validation）。剩下的失败很**分散**，在 discovery 上每类只有 1–2 个：步数不够、关键词过滤漏召回、复制/移动搞混、抄错数字、多加了东西。
- 同一配置重跑一次，成功率的波动约 7pp。所以单条规则带来的 1–5pp 提升，用 2 个 seed 的整体对比根本测不出来。这一点在 D10 上就看得很清楚：
  - H1 上，D10 的触发率是 14%，测出 +15pp（p=0.033）；
  - H2 上，触发率只有 4%，测出 +5.7pp（p=0.22）。
  - 两种情况下，被拦截的 episode 都是全部成功。
- 第一阶段的失败教训是：拿 $\phi$ 去预测 $Y$，学到的是"任务难不难"，这在新任务上不成立。

## 1. rubric = 一棵干预树
- 内部节点：只读前缀的检测器 $\phi_j(\sigma)\in\{0,1\}$。
- 叶子：干预 $\pi\in\{\varnothing,\ \text{note}(\cdot),\ \text{block-once}(\cdot),\ \dots\}$。
- 例：D10 是一棵深度为 3 的树：

  ```
  在调 complete_task?
    └ 是 → 任务里没有提问词?
              └ 是 → answer 非空?
                        └ 是 → 拦一次，并引用规范原文
  ```

- 整个 harness 是一个加法组合：$h_R=h_0\oplus k_1\oplus\cdots\oplus k_R$。多棵树同时触发时，按优先级处理，并且每步最多注入一条提示。

## 2. 记忆树 $\mathcal M$（Dream-RSI 的那部分）
- 每个任务对应一棵前缀树。节点 $v$ 就是前缀状态 $\sigma_v$。同一前缀下，不同 seed 或不同干预的续跑，构成 $v$ 的兄弟子树。
- 每个节点记录三类信息：后代的胜负计数 $(a_v,b_v)$、成功率后验 $p_v\sim\mathrm{Beta}(1+a_v,1+b_v)$，以及在这里试过哪些干预。
- 数据来源：
  - 已有的多 seed 日志构成第一层（根节点下的兄弟分支）；
  - branch-at-fire 的续跑（`boost/branch_build.py` 加上 `BRANCH_NOTE`）会把新的分支挂到对应节点上；
  - 回放是精确的：H1 系列的回放不调用 evaluate，smoke 测试里 20 步全部复现。

## 3. 残差与不确定性（XGBoost 的那部分）
用 logistic 损失，目标是 $y=1$。在节点 $v$ 处：
$$g_v=\hat p_v-1\quad(\text{还不会的程度}),\qquad h_v=\hat p_v(1-\hat p_v)\quad(\text{不确定性}).$$

- $\hat p\approx 1$：$g\approx 0$，不需要修。
- $\hat p\approx 0$：$h\approx 0$，常见原因是环境或 ground truth 本身有问题（例如 ba46d91），权重自然降低。
- 时好时坏的边界节点：$|g|\cdot h$ 最大，信息量最多，也最可能修回来。

候选树 $k$ 的触发集合是 $L_k=\{v:\phi_k(\sigma_v)=1\}$。**筛选用的分裂增益**：
$$\mathrm{Gain}(k)=\frac{\big(\sum_{v\in L_k} w_v g_v\big)^2}{\sum_{v\in L_k} w_v h_v+\lambda}-\gamma,$$
其中 $w_v$ 是同任务配对权重：只在同一任务里"既有成有败"的兄弟之间比较，以此差分掉任务难度 $\alpha_t$，对应 MATH §3 的任务内 IC。$\gamma$ 是复杂度惩罚，对应每棵树的代价，比如多出来的提示长度、可能造成的伤害。

用这个增益回看之前的候选：
- 预算 rubric D12（第 20 步时文档占比高）在 discovery 上触发了 22 个成功、5 个失败，大部分质量落在 $g\approx 0$ 的节点上，增益很低，应该淘汰。实际上我们也按这个理由没跑它。
- D10 的触发集合几乎全是会失败的节点，增益很高。

## 4. 叶子值 = 因果效应，不是预测
叶子 $\pi$ 的价值用 branch-at-fire 来估计。对每个 $v\in L_k$，分别续跑"带 $\pi$"和"不带 $\pi$"，得到
$$\hat{\bar a}_k=\frac{1}{|L_k|}\sum_{v\in L_k}\big(\hat V^{\pi}(v)-\hat V^{\varnothing}(v)\big).$$
这相当于 Newton 步的叶子权重，只是换成了因果版本。由此 $\tau_k=s_k\bar a_k$（稀释定律）：
- $s_k$ 取自全量日志里的触发率；
- $\bar a_k$ 是局部、低方差的估计，相对效率见 MATH §2。

这样就避开了第一阶段的问题：分裂只决定**去哪里找**，准入看的是**同一状态下的因果效应**。

## 5. 准入、收缩、更新
- **准入**：$\bar a_k$ 的下置信界大于 0。用 anytime-valid 置信序列，并分配 α 预算（MATH P4）。
- **收缩 / 学习率 η**：干预的强度，可以是提示、拦一次或强制，也可以是常开或触发。D10 的实验已经显示，规则本身不伤人时，常开和触发效果相同（§5 中 $c(\sigma)\ge 0$ 的区域）。所以对每片叶子都要同时估计"常开版"在非触发节点上的效应，以此决定采用哪种形式。
- 合入后在新的 $h_{r+1}$ 下重新估计 $g,h$。一部分节点会被修好，残差随之转移。H1 → H2 → D10 这一路上已经观察到这种转移：先是预算问题，然后是答案语义问题，现在是分散的长尾。

## 6. 探索（往哪里分支）
沿用 Dream-RSI "选哪些叶子扩展"的思路，但加上不确定性量化：
- 选节点：按 $|g_v|\,h_v\cdot \mathrm{Var}[p_v]$ 做 Thompson 或 UCB，挑出要分支的节点。
- 分配次数：对有前途但还不确定的候选树，追加分支次数（top-two 分配）。
- Dream-RSI 是在同一份历史上做确定性回放后取 argmax，没有不确定性，也没有留出集。我们用后验加 validation 留出来补上这两点。

## 7. self 的部分
proposer 应该由 **Qwen 自己**担任：读 $|g|\cdot h$ 最大的那些节点及其成功的兄弟，提出 $(\phi,\pi)$ 的代码。强模型（或程序）只负责计算 $g,h$、Gain、$\bar a$ 和准入，不提供任务知识。这和 Dream-RSI 限制"只改编排、不解题"是同一种思路，可以弱化"这其实是蒸馏"的质疑。

报告时把干预分成两类，分开报告：
- **控制流类**：拦一次、预算、批处理；
- **任务知识类**：例如 place_order 需要 amazon 的 id。

## 8. 第一批实验
1. **D10 在 H2 上的 $\bar a$**：回放 H2 val 中 4 个被拦截的状态，以及 H2 基线中交了非空答案的状态，分支"拦 / 不拦"。预期 $\bar a\approx 1$，$\tau\approx s\approx 4\%$。
2. **在 H2 + D10 的 disc 日志上建记忆树，排出 $|g|h$ 的前 20 个节点**，检查是否落在诊断 agent 已经找到的那几类上（预算、召回、抄错）。这一步用来检查残差排序是否合理。
3. **Qwen proposer**：只给前 20 个节点和对应的兄弟轨迹，不给 ground truth，让 Qwen 自己提出候选树。之后依次过 Gain 筛选、branch-at-fire 估计、validation 留出。检验标准是它能否在 H1 日志上**自己重新发现 D10**。
